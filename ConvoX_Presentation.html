Overview
What is ConvoX?
2 of 14

ConvoX (सम्पर्क, meaning "connection" or "contact" in Hindi) is a full-stack, production-grade messaging application.

It proves modern web platforms can achieve blazing-fast response times and rock-solid memory safety without sprawling microservice overhead.

Bare-metal C++20 Server

Direct execution via cpp-httplib + OpenSSL with sub-millisecond route resolution.

Embedded SQLite3 Engine

Thread-safe, WAL mode, non-destructive schema migrations, strict foreign-key integrity.

WhatsApp-Style React Frontend

Responsive split-screen messaging, cursor polling, emoji reactions, quotes & file sharing.

Google Stitch Tricolour Design

Indian Tricolour palette (Navy, Saffron, Green) with full dark-mode ergonomics.

Design Philosophy

Fast. Secure. Self-Contained. A single C++ binary serves the API; the React frontend talks to it over HTTP/JSON.

System Design
Full-Stack Architecture
5 of 14

Request Flow

React frontend → Fetch client (HttpOnly cookie + CSRF) → HTTP/JSON → C++ cpp-httplib server (:8080) → CORS origin allowlist.

Controllers (HTTP Layer)

HealthController, AuthController, MessagingController — deserialization & responses.

Services (Business Logic)

AuthService, MessagingService, Validator — business rules & security.

Repositories (Data Layer)

User, Session, Conversation, Message repositories — CRUD via SQLite.

RAII DB Layer

Database + Statement wrappers eliminate resource/memory leaks.

OOP Principles

  • Separation of Concerns — clean Controller / Service / Repository boundary
  • Interface Segregation & Dependency Inversion — pure virtual interfaces for DI & unit testing
  • RAII resource management — no leaks
  • Parameterized SQL (sqlite3_bind_*) — zero SQL injection
  • Thread safety with SQLite WAL mode for concurrent readers

Data Model
Database Architecture
6 of 14

8 interconnected tables with automatic schema migrations, stored in connectx.db (WAL mode).

Core Tables

  • users — id, username, email, password_hash, salt, timestamps
  • sessions — token, user_id, expires_at (HttpOnly cookies)
  • conversations — direct or group, user_low/high_id pair
  • conversation_members — role (admin/member), last_read_message_id

Message & Media

  • messages — body, reply_to_id, read_at, edited_at, is_deleted
  • message_reactions — emoji per user per message
  • attachments — file_name, file_path, mime_type, size (10 MB cap)
  • user_preferences — theme, sound, desktop notifications, read receipts

Integrity Guarantees

  • Foreign keys ON DELETE CASCADE
  • Unique direct-chat pair index (user_low_id < user_high_id)
  • Unique reaction (message, user, emoji)
  • PRAGMA foreign_key_check clean after migrations
  • Zero data loss on legacy schema migration

Sample Schema

CREATE TABLE users (
 id INTEGER PRIMARY KEY AUTOINCREMENT,
 username TEXT UNIQUE NOT NULL,
 email TEXT UNIQUE NOT NULL,
 password_hash TEXT NOT NULL,
 salt TEXT NOT NULL,
 created_at TEXT DEFAULT (datetime('now'))
);

Trust & Safety
Security & Cryptography
8 of 14

🔐 Authentication

  • PBKDF2-HMAC-SHA256 password hashing with unique per-user salts
  • HttpOnly, SameSite=Lax session cookies (no XSS token theft)
  • CSRF origin allowlist on state-changing requests
  • Multi-user session isolation; revocation on password change

💉 Injection Defense

  • 100% parameterized SQL (sqlite3_bind_*) — zero untrusted string concatenation
  • SQL injection immunity across discovery, auth, and search
  • Strict Content-Type & magic-byte validation on uploads

📁 File Safety

  • Magic-byte sniffing (JPEG, PNG, GIF, WebP, PDF, DOCX, DOC, TXT)
  • Null-byte / control-character rejection for disguised payloads
  • 10 MB limit; directory-traversal sanitization
  • Randomized hex filenames; participation-based download access

🔒 Privacy

  • Read-receipt privacy toggle (suppress read timestamps)
  • Soft-delete tombstones preserve thread continuity
  • CORS origin allowlist; untrusted origins get 403 Forbidden
  • Rate limiting (sliding window, HTTP 429)

Get Started
Run Locally on Your Computer
11 of 14

1. Clone

git clone https://github.com/aloknidhi/ConvoX.git
cd ConvoX

2. Backend (C++)

cd backend
make            # builds server + test_suite
make test       # 75 tests pass
./server        # http://0.0.0.0:8080

3. Frontend (React)

cd frontend
npm install
npm run dev     # http://localhost:5173

4. Config

cp .env.example .env
# edit .env: JWT secret, cookie settings, allowed origins

One-Click (Windows)

.\start.ps1
# builds backend, starts C++ server on :8080, launches Vite on :5173

Then visit http://localhost:5173. Press Ctrl+C to stop.

Verify

  • curl http://localhost:8080/health → OK
  • Frontend loads at :5173
  • Register & send a test message

Prerequisites

  • base-devel openssl sqlite (Arch)
  • Node.js + npm
  • WSL recommended on Windows
